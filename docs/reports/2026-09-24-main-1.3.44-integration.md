## Known upstream problems — NOT fixed in this round

### OAuth fatal refresh codes are lost

`worker/internal/oauthcmd/oauthcmd.go` maps typed refresh errors such as invalid_grant, invalid_refresh_token and refresh_token_missing into generic refresh_failed. This loses the classification consumed by Node credential retirement. `src/lib/transport/kernel-router.mjs` also lacks invalid_refresh_token in its fatal matcher. This affects both dataplanes.

A narrow safe-code-preservation repair was investigated. An official, checksum-verified portable Go1.25.1 SDK matching the shipped worker compiler was prepared in the temporary evidence directory. Actual tests could not compile the existing Unix-only credential-store syscall.Flock calls on Windows. The repair was therefore stopped before source/test/binary edits. No platform shim, untested Go fix, or replacement worker was committed. Reopen with an authorized Linux validation route, then verify the real error-envelope/classifier contract and rebuild the shipped worker.

### Crag selection is not consistently honored by lifecycle materialization

Normal startup, missing-payload recovery, engine switch, recreate and an official-init path still call the wrap-only materializer, while configuration can select crag and the official CLI. This can produce a mismatched selected configuration and installed kernel. Relevant areas: `vm-runtime.mjs`, `slot-runtime.mjs`, `vm-recreate.mjs`, and `panel-routes.mjs`; the distinct selected-dataplane helper is in `wrap-cli-runtime.mjs`.

This is an explicit operational gate before enabling/accepting crag, not a new runtime prohibition implemented here. No dataplane setting was changed. Default wrap remains, and no claim is made that it repairs the separate OAuth issue. The lifecycle redesign/repair is outside this bounded rebase and should be tested through actual cold-start/restart materialization before enabling crag.
