## Additional confirmed integration corrections

### Committed authentication failure must not replay through the outer pool

The previous inner guard was insufficient for a confirmed auth error with negative terminal metadata. The classifier could choose continue-and-cooldown before reaching its generic committed stop, letting the outer runner send to account B after account A had already emitted content. This is an existing policy gap, not a claim that the new main introduced it.

Real runner + router + in-memory transport tests reproduced two sends. Confirmed auth policies now stop on committed output while retaining retirement reasons. The cooldown application recognizes those stopped auth policies, so invalid-credential retirement remains intact; diagnostic pins and valid precommit failover keep their existing behavior.

### Official usage must use the selected attempt's mask

The new main set its CLI estimate to zero for official mode but could retain the global or prior-attempt mask. Actual handler tests reproduced totals of 60 or 82 versus raw 100 for overrides and zero-to-official switches. The effective official mask now resets to zero. Other persona policies and raw log accounting are unchanged.

### Tests follow the new upstream contracts

Two prior cancellation tests expected one cleanup recycle. Main now restores that auth error to 401/rejected and avoids killing a healthy CLI, so the correct count is zero. No-replay, cancellation, original failure and usage assertions remain; status and streamError assertions were added.

Two new-main panel tests still mocked a kernel-only release. Updated the mock to provide both assets, retained invalid-kernel/no-write coverage, checked CLI installation into the sample/stopped slot, and added missing/invalid CLI rejection tests. No release-installer production logic was changed.
